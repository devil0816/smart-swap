Smart Swap System Architecture

Comprehensive academic breakdown of software design patterns, entity-relationship structures, security controls, and algorithmic formulations.

1. Modular MVC Blueprint Architecture

Smart Swap is structured adhering strictly to the **Model-View-Controller (MVC)** design pattern using Flask Blueprints for clean decoupling of concerns:

Models (`models.py`): SQLAlchemy ORM declarative classes representing database entities with composite unique constraints and cascading rules.
Controllers / Blueprints (`routes/`): Modular blueprints (`auth`, `main`, `exchanges`, `messages`, `admin`) handling HTTP routing, request parsing, session authentication, and data operations.
Views (`templates/`): Semantic HTML5 templates rendered with Jinja2, utilizing component inheritance from `base.html` and Bootstrap 5 responsive styling.
2. Security & Defensive Engineering

Implemented multi-layered defense to safeguard user integrity and prevent common web vulnerabilities:

  • Cryptographic Password Hashing: Werkzeug's secure hashing (`scrypt`/`pbkdf2`) prevents plain-text credential leaks.
  • CSRF Attack Protection: Flask-WTF cryptographically signed tokens on every state-altering form.
  • SQL Injection Prevention: Parameterized queries guaranteed through SQLAlchemy ORM expressions.
  • Role-Based Access Control (RBAC): `@admin_required` decorators gating sensitive moderation endpoints.
3. Mathematical Formulation of Compatibility Score

The compatibility function $C(U_1, U_2)$ calculates a weighted affinity metric in $O(N)$ time complexity:

$$Score = \min\Big(100,\; W_{\text{skill}} + W_{\text{multi}} + W_{\text{prof}} + W_{\text{sched}} + W_{\text{loc}} + W_{\text{rating}}\Big)$$
$W_{\text{skill}}$ (Core Overlap)
• Mutual 2-Way: +55 pts
• One-way Mentor: +35 pts
• One-way Learner: +25 pts
• Category affinity: +15 pts
$W_{\text{prof}} + W_{\text{sched}}$ (Alignment)
• Advanced/Expert mentor: +10 pts
• Multi-skill pair: Up to +15 pts
• Schedule match / Flexible: +10 pts
$W_{\text{loc}} + W_{\text{rating}}$ (Trust & Mode)
• Location/Remote match: +10 pts
• Top Community Rating (4.5★+): +10 pts
• Good Rating (4.0★+): +5 pts
4. Entity-Relationship (ER) Schema Specifications
Table Primary Key Foreign Keys & Constraints Functional Responsibility
users id unique(username, email) Stores member profiles, hashed passwords, availability, and administrative status.
skills id unique(name) Standardized catalog of skills mapped across 8 domain categories.
user_skills id FK(user_id, skill_id), uq(user_id, skill_id, skill_type) Many-to-Many bridge table tracking teaching vs learning roles and proficiency.
exchange_requests id FK(sender_id, receiver_id, offered_skill_id, requested_skill_id) Core state machine: pending → accepted → completed.
messages id FK(sender_id, receiver_id, exchange_id) Threaded communication history supporting real-time AJAX transport.
reviews id FK(exchange_id, reviewer_id, reviewee_id) Verified post-completion feedback enforcing 1-to-5 star reputation metrics.
notifications id FK(user_id) In-app reactive alerts for proposals, status updates, and incoming messages.
reports id FK(reporter_id, reported_user_id) Community moderation tickets reviewed by platform administrators.
